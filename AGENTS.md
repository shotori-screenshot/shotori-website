## Development

When starting the dev server, use background mode:

```
astro dev --background
```

Manage the background server with `astro dev stop`, `astro dev status`, `astro dev logs`.

## This repo

- Package manager is **pnpm** (`pnpm install` / `pnpm dev` / `pnpm build`).
- Landing page (`src/content/docs/index.mdx` + `zh-cn/index.mdx`): layout via
  **Tailwind 4** utilities + typography component classes in
  `src/styles/landing.css`; animated demos are **React islands**
  (`src/components/landing/*.tsx`, `motion` library, `client:visible`).
  `landing.css` deliberately skips Tailwind preflight and is imported only by
  `src/components/landing/boot.astro`, so docs pages never load it. Starlight
  prose selectors (`.sl-markdown-content h2`) outrank single-class Tailwind
  utilities — style headings/paragraphs with the `.t-*` classes in
  `landing.css`, Tailwind only for layout on wrappers. Keep new landing
  animations freeze-safe (every frame complete; no opacity-0 entrances —
  Chromium throttles off-viewport animations and full-page screenshots render
  blank chunks).
- Bilingual site: English content lives at `src/content/docs/` (root locale),
  简体中文 at `src/content/docs/zh-cn/`. The two trees must stay in sync
  page-for-page — when you add or move a page, do it in both. Missing pages
  fall back to English.
- `defaultLocale` must stay `'root'` (with `locales.root` for English). Using
  `defaultLocale: 'en'` + `locales: { en: … }` silently expects English under
  `docs/en/` with an `/en/` URL prefix — the root-level English pages then get
  locale `'en'`, match no `en/`-prefixed routes, and **every English sidebar
  entry silently disappears** (autogenerated and manual `slug` items alike).
- Starlight does not prefix hero `link` values or root-relative links in
  content with any deployment base, so they 404 whenever the site is served
  under a subpath. Write site-internal links **relative**
  (`getting-started/installation/`, not `/getting-started/installation/`) —
  relative links resolve correctly under any base and per locale. Sidebar
  links are safe; they are generated with the base applied.
- Content is distilled from the main repo's `README.md` / `README.zh-CN.md`;
  reuse their wording where possible so the site and READMEs don't drift
  apart.
- Branding assets under `src/assets/` are copies from the main repo's
  `assets/` directory — re-copy rather than redesign when they change.
- Card icons use Iconify full names (`mdi:...`), resolved at build time; an
  unknown icon name is a build-time error, not a runtime one.
- `site` in `astro.config.mjs` must match the deployed domain — currently
  `https://shotori.mengh04.top` (Vercel + Aliyun DNS); update it whenever
  the domain in the Vercel project changes.
